# Админка запуска «Союз с собой»

Рабочая админка команды. В ней три раздела.

- **Контент-план.** Календарь публикаций по каналам: открытый ТГ, закрытый ТГ, сторис, рилс, email. У каждого дня есть смысл (кому говорим, сцена, мост к продукту) и карточки публикаций со статусом: запланировано, в работе, готово, опубликовано. При первом запуске план загружается из [data/content-plan-v3.json](data/content-plan-v3.json), это выгрузка [редакционной карты](https://maestrovladd.github.io/dari-hub/progrev-v3.html) от 19 октября.
- **Статистика.** По каждому каналу считаем количество публикаций, охват и переходы по ссылке за выбранный период, отдельно по дням. Есть свои трекинг-ссылки для подсчёта переходов.
- **Финансы.** План по выручке, текущая выручка, процент выполнения, число оплат, средний чек, таблица оплат (тариф, способ оплаты, кто закрыл, статус) и разбивка по тарифам, менеджерам и способам оплаты.

Локально внешние библиотеки не нужны: Python 3.9+ и SQLite, данные лежат в `data/admin.db`. На Vercel данные хранятся в Postgres (Neon).

## Запуск на своём компьютере

```bash
cd admin
python3 server.py adduser you@example.com "Имя"
python3 server.py
```

Откройте http://127.0.0.1:8787. Каждому члену команды заводится своя учётка той же командой `adduser`. Если запустить её повторно с той же почтой, она сменит пароль.

Другие команды:

| Команда | Что делает |
|---|---|
| `python3 server.py sync` | собирает данные из всех включённых интеграций |
| `python3 server.py sync instagram` | собирает данные из одного источника |
| `python3 server.py reseed-plan` | **стирает** контент-план и загружает его заново из JSON |

## Откуда берутся цифры в статистике

На каждый день и канал считаются три числа: публикации, охват и переходы.

1. **Автоматически.**
   - Публикации: сколько постов нашла интеграция. Если интеграции нет, считаются единицы контент-плана со статусом «Опубликовано».
   - Охват: сумма охватов из интеграции.
   - Переходы: клики по трекинг-ссылкам этого канала, привязанным к этому дню.
2. **Вручную.** Число, вписанное в таблицу «По дням», заменяет автоматическое и выделяется цветом. Если стереть число, вернётся автоматическое значение.

**Трекинг-ссылки.** Ни Telegram, ни Instagram не отдают переходы по ссылкам в постах, поэтому переходы считаем сами. В разделе «Статистика» создаётся короткая ссылка вида `https://<адрес-админки>/go/tg-2010`. Её ставят в пост вместо прямой, и она переадресует на исходный адрес. Превью ссылок в мессенджерах переходами не считаются. В исходный адрес стоит добавить UTM-метки, тогда GetCourse тоже увидит источник.

## Интеграции

Подключаются во вкладке **«Настройки → Интеграции»**. Ключи хранятся в базе админки только на запись: после сохранения их нельзя посмотреть, только заменить. В ответы сервера они не попадают. Кнопка «Проверить и обновить» сразу собирает данные и показывает результат или ошибку.

Для локального запуска можно по-прежнему использовать `config.json` (шаблон: [config.example.json](config.example.json)). То, что сохранено в форме, имеет приоритет.

Сбор по расписанию: Vercel Cron раз в день плюс задание на cron-job.org раз в час. Адрес для cron-job.org с ключом показан в той же вкладке.

### GetCourse: оплаты

Вариантов три, их можно совмещать. Номер заказа GetCourse не даёт появиться дублям.

1. **Импорт CSV.** Работает уже сейчас. В GetCourse выгрузите заказы в CSV и загрузите файл кнопкой «Импорт CSV из GetCourse» во вкладке «Финансы». Колонки распознаются по названию: номер, дата, пользователь, email, состав заказа, стоимость, оплачено, статус, менеджер. При повторном импорте заказы обновляются, а поля, которые команда заполнила руками, сохраняются.
2. **Выгрузка по API раз в час.** API входит в платные тарифы GetCourse, отдельно за него не платят. Ключ выдаёт владелец или администратор аккаунта в настройках, раздел API. Ему нужно право экспортировать заказы. Заполните `getcourse.domain` (`school.dari-malakhovskaya.ru`) и `getcourse.api_key`. GetCourse ограничивает число выгрузок, поэтому чаще раза в час запускать не стоит.
3. **Вебхук.** Оплата появляется сразу. В GetCourse создайте процесс по заказам с операцией «Вызвать URL» на адрес `https://<адрес-админки>/hooks/getcourse?token=<webhook_token>&id=…&status=…&cost=…&payed=…`. Пример с переменными есть в «Настройках» админки, точные названия переменных берите из редактора процесса. Без верного `token` вебхук не принимается.

Способ оплаты (карта, рассрочка, кредит) в выгрузке заказов может не прийти. Тогда его выбирают в таблице вручную, это занимает секунду.

### Instagram: сторис и рилс

Используем вход через Instagram: страница Facebook для этого не нужна.

1. Аккаунт Instagram должен быть профессиональным (бизнес или автор).
2. На developers.facebook.com создайте приложение типа «Бизнес» и добавьте в него продукт Instagram, вариант «API с входом через Instagram».
3. В разделе «Создание маркеров доступа» добавьте аккаунт Дари, разрешите доступ и нажмите «Создать маркер». Нужны только права `instagram_business_basic` и `instagram_business_manage_insights`.
4. Рядом с аккаунтом показан его ID (цифры) — это `user_id`, а созданный маркер — `access_token`. `graph_host` оставьте `graph.instagram.com`.

Маркер живёт 60 дней, затем его нужно создать заново (или продлить запросом `refresh_access_token`).

Что собирается: охват каждой сторис и просмотры каждого рилс. **Сторис доступны через API только 24 часа**, поэтому синхронизация должна идти хотя бы раз в сутки, лучше раз в час. Переходы по стикеру-ссылке API не отдаёт, их считают трекинг-ссылки.

### Telegram: просмотры постов

Бот-API Telegram просмотры постов не отдаёт, поэтому они читаются через аккаунт подписчика (библиотека Telethon).

1. Заведите **отдельный** аккаунт и подпишите его на оба канала **без прав админа**. Если у аккаунта есть права админа в выбранном канале, синхронизация откажется работать.
2. На my.telegram.org получите `api_id` и `api_hash` и сохраните их в форме.
3. В форме введите номер аккаунта, нажмите «Получить код» и введите код из Telegram. Если стоит облачный пароль, введите и его.
4. Нажмите «Загрузить список каналов», выберите открытый и закрытый каналы и сохраните.

Сессия аккаунта хранится в базе админки. Завершить её можно кнопкой «Отключить» или в Telegram: «Настройки → Устройства».

### Email

Статистику рассылок GetCourse по API не отдаёт. Количество и открытия вписываются вручную из отчёта о рассылке, переходы считают трекинг-ссылки.

## Деплой на Vercel

Код лежит в приватном репозитории GitHub `ai-workspace-aura/dari-malakhovskaya`, в папке `admin/`. После каждого пуша в `main` Vercel сам обновляет сайт.

Настройка выполняется один раз:

1. **Проект.** На vercel.com нажмите Add New → Project, подключите GitHub и выберите репозиторий `dari-malakhovskaya`. В поле **Root Directory** укажите `admin`, Framework Preset оставьте Other. Нажмите Deploy.
2. **База.** В проекте откройте Storage → Create Database → Neon (Postgres), выберите бесплатный план и подключите базу к проекту. Vercel сам добавит переменную `DATABASE_URL`.
3. **Первая учётка.** Откройте сайт: пока пользователей нет, он предложит создать учётку. Сделайте это сразу после деплоя.
4. **Интеграции** подключаются в самой админке, во вкладке «Настройки». Переменные окружения не нужны. Необязательные: `CRON_SECRET` (без неё ежедневный Vercel Cron не запустится, но cron-job.org работает и так) и `ADMIN_BOOTSTRAP_EMAIL`/`ADMIN_BOOTSTRAP_PASSWORD`.

Новых пользователей добавляйте с компьютера: в `DATABASE_URL` подставьте адрес базы из Vercel. Перед этим один раз выполните `pip3 install pg8000`.

```bash
DATABASE_URL="postgres://..." python3 server.py adduser colleague@example.com "Имя"
```

**Синхронизация по расписанию.** Vercel Cron на бесплатном тарифе запускается раз в день, в 08:00 по Москве (см. [vercel.json](vercel.json)). Сторис живут 24 часа, поэтому раз в день мало. Добавьте бесплатное задание на cron-job.org, раз в час. Адрес с ключом есть в «Настройках → Интеграции».

**Ограничения Vercel.**
- Одна синхронизация длится не дольше 60 секунд. Если GetCourse не успел подготовить выгрузку за это время, её заберёт следующий запуск.
- Instagram API из функций Vercel доступен, потому что серверы находятся не в России.

### Свой сервер вместо Vercel

Админка работает и на любом VPS с Python 3.9+. Там используется SQLite, и переменная `DATABASE_URL` не нужна. Синхронизацию по расписанию тогда задаёт `sync_interval_minutes` в `config.json`. Запуск через systemd: `ExecStart=/usr/bin/python3 server.py` в папке админки, HTTPS через Caddy (`reverse_proxy 127.0.0.1:8787`).
